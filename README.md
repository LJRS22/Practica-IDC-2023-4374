## Mapa de las Nueve Familias de Etiquetas HTML5

| Familia | Página y sección | Etiquetas usadas | ¿Por qué esa etiqueta? |
|---|---|---|---|
| 1. Cimientos | Las tres páginas (`index.html`, `servicios.html`, `contacto.html`) en la raíz del documento y `<head>` | `<!DOCTYPE html>`, `<html lang="es">`, `<head>`, `<meta charset="UTF-8">`, `<meta name="viewport">`, `<title>`, `<meta name="description">`, `<body>` | Definen que el documento sigue el estándar HTML5, establecen el idioma español para lectores de pantalla y buscadores, aseguran la codificación correcta de tildes/ñ, adaptan el ancho a móviles y dan un título y descripción únicos a cada página. |
| 2. Encabezados y párrafos | Las tres páginas, distribuidos en `<header>`, `<main>`, `<section>`, `<article>` y `<aside>` | `<h1>`, `<h2>`, `<h3>`, `<p>` | Estructuran la jerarquía temática del contenido sin saltos de nivel (`h1` para el título principal de cada página, `h2` para secciones primarias y `h3` para subtemas), mientras que `<p>` agrupa cada bloque de texto clínico en párrafos legibles. |
| 3. Texto, citas y código | `index.html`, secciones `#quienes-somos` y `#novedades` | `<strong>`, `<em>`, `<mark>`, `<del>`, `<ins>`, `<abbr>`, `<small>`, `<sub>`, `<sup>`, `<blockquote>`, `<cite>`, `<q>`, `<code>`, `<kbd>`, `<pre>`, `<var>`, `<time>` | Aportan significado semántico real al texto: `<strong>` para urgencia/importancia, `<abbr>` para siglas médicas (OMS, FIMS), `<del>` e `<ins>` para cambios de precios reales, `<sub>`/`<sup>` para fórmulas fisiológicas (VO2 máx), `<blockquote>` y `<cite>` para citas de autoridad médica, y `<kbd>`/`<code>`/`<pre>` para atajos de teclado y reportes del sistema clínico. |
| 4. Listas | `servicios.html`, sección `#especialidades-y-pasos` (y `<nav>` en las 3 páginas) | `<ul>`, `<ol start="1" type="1">`, `<li>`, `<dl>`, `<dt>`, `<dd>` | Se usó `<ul>` con una sublista anidada dentro de `<li>` para agrupar especialidades sin orden estricto; `<ol>` para el protocolo de atención porque los pasos diagnósticos llevan un orden secuencial obligatorio; y `<dl>` para definir el glosario de términos médicos del centro. |
| 5. Enlaces | `contacto.html`, sección `#canales-directos` y menú `<nav>` en las 3 páginas | `<a href="...">` con rutas relativas, `#id`, `mailto:`, `tel:`, `download` y `target="_blank" rel="noopener"` | Permiten conectar las tres páginas entre sí, saltar directamente al formulario dentro de la misma página (`#formulario-cita`), iniciar llamadas o correos desde dispositivos móviles, descargar la guía del paciente y abrir el portal del Ministerio de Salud Pública de forma segura sin exponer el `window.opener`. |
| 6. Imágenes y multimedia | `servicios.html`, sección `#multimedia` | `<figure>`, `<img alt="...">`, `<figcaption>`, `<video controls>`, `<source>`, `<iframe title="...">` | `<figure>` y `<figcaption>` asocian semánticamente la imagen del laboratorio con su pie de foto; el atributo `alt` describe lo que ocurre en la escena para usuarios con discapacidad visual; `<video>` permite reproducir la demostración de fisioterapia con controles nativos; e `<iframe>` incrusta el mapa de ubicación con `title` accesible. |
| 7. Tablas | `servicios.html`, sección `#tarifario` | `<table>`, `<caption>`, `<thead>`, `<tbody>`, `<tfoot>`, `<tr>`, `<th scope="col/row">`, `<td rowspan/colspan>` | Se eligió para presentar datos tabulares reales (precios, duración y cobertura ARS de estudios médicos). `scope="col"` y `scope="row"` vinculan encabezados con celdas para accesibilidad, `rowspan` agrupa dos estudios del mismo departamento y `colspan` resume el paquete completo en el `<tfoot>`. |
| 8. Formularios | `contacto.html`, sección `#formulario-cita` | `<form>`, `<fieldset>`, `<legend>`, `<label for="">`, `<input>` (text, email, tel, number, file, date, time, range, radio, checkbox), `<select>`, `<optgroup>`, `<option>`, `<textarea>`, `<button type="submit">` | Permite capturar la reserva de citas dividiendo los datos lógicamente en dos `<fieldset>` (datos del paciente y detalles de la cita). Cada control tiene su `<label>` vinculado por `for`/`id` y usa validación nativa (`required`, `pattern`, `min`, `max`, `minlength`) para evitar envíos erróneos sin depender de JavaScript. |
| 9. Semántica y div/span | Las tres páginas (estructura global y bloques de formulario) | `<header>`, `<nav>`, `<main>`, `<section>`, `<article>`, `<aside>`, `<footer>`, `<details>`, `<summary>`, `<address>`, `<div>` | Organizan el esqueleto del documento por el rol de cada bloque: un único `<main>` para el contenido central, `<article>` para la noticia autónoma del laboratorio, `<aside>` para avisos complementarios, `<details>`/`<summary>` para preguntas frecuentes desplegables, `<address>` para datos de contacto y `<div>` únicamente para agrupar pares de `label`/`input` dentro del formulario donde no aplica una etiqueta semántica de sección. |
